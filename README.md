# MLOps Practical Lab — Five Experiments

**Purpose:** A reproducible, student-friendly practical project covering MLOps fundamentals, Git collaboration, DVC data/version tracking, data pipeline automation, and a minimal feature store.

## Run the Python practicals

Use Python 3.10+ from a terminal opened in this project folder:

```bash
python scripts/run_python_experiments.py
```

This executes Experiments 1, 2 (environment check), 3 (dataset creation), 4 (data pipeline), and 5 (feature store). It does not pretend to run DVC commands if DVC is not installed.

## Run the real DVC practical (important)

DVC is a separate CLI tool. Running a normal Python script does **not** prove DVC is installed or working. Open a terminal in this folder and run:

```bash
python -m pip install -r requirements.txt
python scripts/run_dvc_practical.py
```

The DVC script checks for the DVC CLI, initializes DVC if needed, configures a local DVC remote, runs the versioned pipeline with `dvc repro`, and pushes tracked outputs to the local remote with `dvc push`. It exits with a clear error if DVC is unavailable; it will not create fake DVC output.

After a successful run, show your teacher these commands and their actual output:

```bash
dvc --version
dvc status
dvc dag
dvc repro
dvc push
```

A local remote is used for a self-contained lab. It demonstrates DVC tracking and reproducibility, but is not a cloud remote. To use Google Drive, S3, or another remote, configure that remote separately.

## Git/GitHub practical

Run `git --version`, then follow `experiment-2-git-github/README.md`. GitHub upload is a separate step requiring your account. This ZIP does not claim to have pushed to your personal GitHub.

## Project structure

- `experiment-1-mlops-introduction/` — concepts and workflow diagram.
- `experiment-2-git-github/` — repository, branching, merge-conflict exercise.
- `experiment-3-dvc/` — DVC setup, data versioning, status/repro/push.
- `experiment-4-data-pipeline/` — data validation, preprocessing and feature engineering.
- `experiment-5-feature-store/` — SQLite-backed offline feature store demo.
- `dvc.yaml` — executable DVC pipeline definition.
- `reports/` — consolidated report and honest completion checklist.
- `evidence/` — outputs produced by the Python validation run; DVC evidence is to be generated by running DVC locally.

## Important evidence note

Files in `evidence/` are generated by the included Python experiments in the packaging environment. DVC CLI evidence is intentionally not prefilled because DVC was not installed in the packaging environment. Run the DVC practical on your own machine to generate authentic terminal output for submission.
